### 一、项目背景

- **figma地址**
- **项目背景：**
	对象标识图谱，通过解析对象标识，以图谱的形式展示出扩展属性标识关联关系；其中，应用管理员还可通过勾选对象标识属性的方式，来进行数据共享任务发起操作，并在对象标识图谱中，进行记录。

- **大致功能：**
	- 首次进入图谱，图标默认扩展至三层；
	- 鼠标上移对象圆框，显示对象信息气泡，且该圆框与其有关联的第一层数据将高亮显示：鼠标移出后，除图框外，连接线也高亮显示，并显示流动线条；效果消失；
		- a) 对象标识编码
		- b) 省级：对象标识所属省级节点名称；
		- c) 企业：对象标识所属企业节点名称；
		- d) 应用：对象标识所属应用系统名称；
		- e) 查看对象标识：点击查看对象标识，显示属性详情信息框，展示该对象下所有的基础属性与扩展属性；基础属性与扩展属性均可进行展开、收起操作；点击信息框右上方【关闭】按钮，可关闭该信息框。鼠标点击其他位置时，该图框自动关闭。
	- 当单击某一圆框时，与其有关联的第一层数据将高亮显示，除图框外，连接线也高亮显示，并显示流动线条，该效果进行固定展示，且鼠标移出后，该效果也不会消失，直至鼠标点击空白处或其他交互时，该效果消失；
	- 线条交互：当鼠标上移或点击某一连接线条时，线条高亮显示，并显示流动线条。
	- 图谱操作说明：
		- 图谱中，默认展示三层扩展图框，且前三层无法进行折叠；可点击圆框后方的“+”、“-”图标进行数据的扩展或隐藏；扩展或隐藏时，将显示所有该对象标识的扩展属性数据，或隐藏所有该对象标识的扩展属性；若某一对象标识无扩展属性，则不现实“+”号；
		- 图谱中，可通过放大缩小滑块放大缩小图谱；
		- 点击【适应画布】按钮，将图谱视图大小还原为用户首次进入时的大小；

### 二、框架选型

| 特点 | antv/g6 | relation-graph | echarts | d3 |
|---|---|---|---|---|
| 定制能力 | 高（支持自定义注册节点、边、文本等功能） | 中（预设交互完善，深度定制需改源码） | 中（配置驱动，复杂交互需扩展） | 极高（完全掌控渲染逻辑） |
| 开发效率 | 中高（API 规范，但需掌握图语法） | 高（Vue 开箱即用） | 高（配置化+丰富示例） | 低（需手写 SVG/Canvas 逻辑） |
| 性能表现 | 高（WebGL 加速，支持 10k+ 节点） | 中（Canvas 渲染，中等数据量） | 中高（大数据需优化配置） | 极高（手动优化极限性能） |
| 交互功能 | 强（拖拽/连线高亮/右键菜单） | 强（节点聚焦/关联线高亮） | 基础（点击/悬停，复杂交互弱） | 需完全自实现 |
| 学习成本 | 中高（需理解图布局算法） | 低（Vue 友好） | 低（中文文档完善） | 极高（掌握底层原理） |
| 生态扩展 | 完善（AntV 家族工具链支持） | 弱（专注关系图，生态较小） | 强（社区插件丰富） | 自由（依赖 JS 生态） |
| 移动端兼容 | 兼容，因为dom事件完全暴露 | 难兼容，需要修改源码更改移动端点击事件 | 不兼容，很难做到和移动端屏幕自适应，并且不支持事件扩展 | 兼容，接近于svg原生底层，需要自己写移动端事件 |

基于业务实现方案，需要支持半定制化的绘图工具，即可以支持绘图的基本布局，又可以将每个节点以及连接线、小球动画、高亮、扩展收起、拖拽等功能单独设计开发。采用了antv/g6来实现，虽然学习成本属于中高，需要考虑节点以及动画的布局算法，但是对于大量数据渲染的性能以及使用的流畅度，功能扩展度、定制灵活度等方面，此框架是不二的首选。

### 三、功能亮点

- 定制化连接线：贝塞尔曲线，并且附带绘制曲线箭头，跟随拖拽可以任意拉伸、收缩
- 定制化层级布局：环形关联数据情况下，按照层级从左到右依次布局
- 定制化交互形式：支持画布，节点任意拖拽，点击高亮展示多向关系轨迹图
- 定制化子节点收起展开状态：可以收起子节点下面关联的所有子节点以及相互关联的所有连接线
- 定制化多向关系小球流动动画：小球通过二次贝塞尔沿着曲线运动，支持多向关联轨迹运动
	> 以上功能全部需要兼容画布拖拽，缩放，自适应以及单个节点拖拽

### 四、技术难点

#### 1、箭头以及曲线连接线的自定义绘制
首先会有人问为什么采用曲线代替直线，为什么不采用框架内置层级布局方法？这样会省去很多需要手动计算的方法？
请至钉钉文档查看附件《第一版.mp4》

如视频和图片所示，第一版采用的是框架内置的力导向drage布局，但是会产生一个问题，就是每次扩展子节点，系统会对新的节点重新排列，导致之前的节点位置没办法固定，特别是有回向关联的时候，那么整个节点布局都会随着系统内置布局而改变。采用曲线才是因为遇到双向关联的时候，路径可以绘制两条产生回环效果，直线则只有一条并不能清晰的展示出双向关联关系。

为了解决以上的问题，采取以下方案：
- 采用自定义曲线绘制，需要考虑连接线的弧度计算，曲线箭头的方向绘制

#### 2、小球动画的实现
小球运动需要考虑以下几点环境因素：
- 需要判断点击节点的时候才出小球运动动画
- 小球多方向关联的动画路径绘制
- 点击空白画布的时候取消小球运动
- 点击另一个节点的时候，需要取消上一个小球运动的所有实例
- 多次点击同一个节点只生成一个小球实例，并不会生成多个
- 拖拽画布或者某个节点小球的运动轨迹实时更新

**核心代码如下：**
- 判断多方向关联运动：过滤出小球多向关联轨迹的source和target，然后进行重绘
- 通过运动轨迹的曲线弧度率计算每帧运动的轨迹
- 在进行拖拽操作的时候更新动画路径的计算
- 点击其他节点时候或者画布的时候，需要清除所有小球实例

#### 3、节点的布局计算、排序（重点）
环形关联前提下，如果按照从左向右的层次布局，那么需要手动计算各个子节点的x和y轴，需要考虑以下几点：
- 每次动态获取数据，如何将每层节点按照层级计算x轴的值
- 点击父节点展开子节点，在未知当前层级一共有多少个子节点情况下，如何计算Y轴的值，保证节点小球不重叠
- 同理，在未知当前有多少个子节点的情况下，如何排序计算每个子节点Y轴的值来保证展开的线不交叉，并靠近各自的父节点
- 拖拽画布或者子节点，点击展开加载新的子节点，如何不触发整个画布的重绘，并且实时更新当前画布的矩阵偏移量

#### 4、自定义节点的收起
在多层级并且为环形关联的条件下，节点的收起需要考虑以下几点环境因素：
- 收起父节点时，如何过滤出子节点以及子节点的子节点... ，并且将这些节点关联的所有线找到
- 收起父节点时，子节点的子节点的按钮状态如何同步
- 收起父节点时，如何进行重排操作

**实现思路：**
- 首先通过递归计算，找出当前父节点下所有子节点，以及子节点的子节点...
- 通过返回值，将找到的所有子节点过滤出所有的source和target的连接线
- 更新当前按钮以及所有子节点的按钮，隐藏当前节点以及所有子节点的节点以及连接线，并同步数据源

#### 5、自定义高亮的实现
高亮和收起操作同理需要考虑以下几点：
- 点击画布空白处，如何需要取消所有高亮状态
- 点击当前节点，如何把所有相关联的节点以及连接线全部高亮，其他节点变暗
- 点击其他节点，如何取消之前的高亮状态

**核心代码如下：**
通过点击当前节点id来获取所有关联的节点，遍历所有的节点，通过setItemState设置每条需要高亮的线和节点，并且触发重绘，执行注册节点的draw函数

#### 6、画布放大、缩小、适应画布、重置视图附带进度条的功能实现
- 如何监听鼠标、触摸板滚轮事件，让图谱实时放大缩小并且流畅不卡顿，进度条进度也随之变化
- 缩放、放大、适应画布、重置画布如何实时更新进度条
- 如何在toolbar里创建原生进度条，如何控制进度的步长以及进度值可以符合画布缩放状态

**实现思路：**
- 首先在toolbar content中创建原生input进度条，设置最小和最大的范围以及步长为0.1。默认1为初始大小
- 其次创建updateSliderValue方法，监听画布滚轮事件，以及画布放大、缩小、重置、适应画布等功能，执行时候，统一调用updateSliderValue获取当前画布的缩放率，做滑动进度条实时赋值更新。注意监听滚轮事件因为实时触发，需要做防抖处理
- 在重置画布的时候，需要将slider滑块进度条回归到默认状态

#### 7、优化
0.竖屏小球很多的情况，溢出屏幕怎么处理？
这个问题是会上讨论完遇到的问题，因为之前的Y轴排序方案是按照600高度范围内计算的，如果有极限情况存在，比如父节点展开下面的子节点有超过10个20个的情况下，那么会溢出当前可视范围，小球会部分重叠在一起，就不会直观的看到当前层级的小球关联情况，经常一番思考，遇到这个问题的解决思路如下：

**核心代码如下：**
```js
// 获取溢出当前可视区域的高度
const isOverClientaHeight = window.innerHeight - (layerCollect.value.get(currentLayer) * (ballSize + baseSep) - baseSep) < 0; 

// 获取溢出的小球个数
const restBallNum = Math.floor((window.innerHeight - (layerCollect.value.get(currentLayer) * (ballSize + baseSep) - baseSep)) / (ballSize + baseSep));

// x,y轴的计算
sameCdLayerNodeData.forEach((d, idx) => {
// 先算出第一个基准Y轴的起始点, 通过当前有层级有几个子节点来计算      
		if(!isOverClientaHeight) {
				countY += idx === 0 ? ballSize : maxYHeight /         
				layerCollect.value.get(currentLayer);
		} else {
				countY += idx === 0 ? (restBallNum * (ballSize + baseSep)) / 2         : (ballSize + baseSep);
		}
		d.y = countY;
		d.x = d.parentNode.x + 220;
});
```
